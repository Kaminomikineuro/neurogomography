# Продуктовый фильм и живые демо-окна

Маршрут F. Источники: [Rieranthony/product-film-skill](https://github.com/Rieranthony/product-film-skill) (MIT) —
продуктовый ролик на дизайн-системе самого продукта (Remotion); [MengTo/Skills `html-demo`](https://github.com/MengTo/Skills)
(MIT) — «записанное» окно приложения на странице, которое на самом деле HTML; [whaleyxbt/claude-motion](https://github.com/whaleyxbt/claude-motion)
(MIT) — числа вкуса из выпущенных роликов. Вкус пользователя/продукта всегда выше любых правил отсюда.

Установка оригиналов (если нужен их полный kit):
```text
/plugin marketplace add Rieranthony/product-film-skill
/plugin install product-film@product-film-skill
```
```bash
npx skills add MengTo/Skills --skill html-demo
```

## 1. Непреложное (product-film)

- **Их дизайн побеждает.** Токены, компоненты, правила, лендинг, копирайт продукта. Никакого чужого вкуса.
- **Спрашивай, не додумывай** — что показывает фильм, решает пользователь (интервью ниже). Варианты — из найденного в их коде, не общие.
- **Каждый кадр — функция времени.** Компонент со своим таймером получает «покадрового близнеца».
- **Измеряй, не угадывай:** биты — из аудио, позиции — из DOM (debug-оверлей), цвета — из декодированных пикселей финального файла.
- **Честные обещания:** только то, что продукт реально делает; одобренные формулировки.
- **Спроси перед** коммитом, пушем, публикацией. Храни каждую версию (`out/<film>/v1`, `v2`…).

## 2. Интервью (AskUserQuestion, ≤ 4 вопросов за раз, рекомендация первой)

**Раунд 1 — бриф:** где покажут (лендинг без звука в цикле / соцсети со звуком / запуск, демо); длина (20–30 / 30–45 /
45–60 / 60–90 с); музыка (их лицензированный трек или стемы / безроялтиевый, который я предложу / без звука); какие
фичи обязательны (3–4 сильнейших по их названиям); формат 16:9 / 9:16 / 1:1 для соцсетей.
**Раунд 2 — ингредиенты:** что несёт бренд (анимация логотипа / маскот, только если есть / вордмарк и теглайн /
только UI); как появляются слова (большие панчлайны между сценами / короткие подписи / без слов); как связаны
сцены (magic moves / один большой холст с камерой / чистые склейки в бит); что ещё (курсор, логотипы партнёров,
моменты-доказательства, их фирменная текстура).
**Не спрашивай** то, на что отвечает код (цвета, шрифты, радиусы) и вкус, который можно показать: сделай 3 style frames.

## 3. Форма истории (30–60 с)

1. **Открытие (1–2 такта):** бренд оживает — логотип рисуется, вордмарк приземляется или hero-экран уже движется. Что-то движется в первую секунду.
2. **Кто и что (1 такт):** панчлайн «Знакомьтесь, X.» или обещание одной строкой.
3. **Фичи (3–6):** опциональный панчлайн ≤ 6 слов → сцена 2–4 такта с реальным UI.
4. **Сильный момент — на дроп песни:** автоматизация включается, результат появляется, до/после.
5. **Доказательство (опц.):** результат поиска, ответ ИИ, метрика, цитата — каждая своей сценой.
6. **Финал:** их теглайн, CTA/URL, логотип.
7. **Цикл:** последний кадр = кадр 0 (декодируй и сравни).

Бюджет: открытие 1–2 такта, панчлайн 1–1,5, фича 2–4, доказательство 1,5–2,5, финал 2. При 150 BPM доля 0,4 с, такт
1,6 с; без музыки всё равно планируй на сетке 120 BPM. **На каждой доле что-то происходит.** Чекпойнт до сборки:
beat sheet + 3 style frames (открытие, фича, сильнейший момент).

## 4. Ингредиенты — как делать хорошо

**Панчлайны:** на экране только слова; ≤ 6 слов, ≤ 2 строк; одно слово/группа на долю (быстрее восьмых — нельзя);
каждое слово влетает из blur ~16 px, поднимается ~36 px и приземляется за 0,3 с на `cubic-bezier(0.22,1,0.36,1)`;
выход — быстрый blur. **Каждое слово держит свой слот до приземления** — строка никогда не перецентровывается.
Ключевые слова — акцентом. Кегль 120–160 px на 1080p; длинную карточку уменьшай, а не переноси в 3 строки.
**Подписи (вместо панчлайнов):** одна строка в фиксированной полосе, держится ≥ 4 долей, смена на спокойной доле.
**Сцены:** только собственный текст UI; body ≥ 24 px, заголовки ≥ 34 px на 1080p; одна идея на сцену.

**Magic moves** (элемент, существующий в обеих сценах, переезжает; остальное blur-swap):
аватары диаграммы → строки списка; ячейки списка → ячейки графика; кликнутая строка → шапка детального вида;
кнопка → активная половина тумблера; логотипы доказательств → слоты финального заголовка.
Правила: одинаковое отношение line-height у путешественника и цели (движение — только масштаб); переезд на
пружине (stiffness ~150, damping ~20); **текст никогда не летит поверх текста** — двигай картинки и знаки, слова blur-out/in.
**Камера по большому холсту:** тяжёлая пружина, наезды на ключевых моментах, зум в log-пространстве.
**Склейки в бит:** точно на долю или такт; фон и акцент совпадают через склейку.

**Курсор:** системная стрелка, едет по лёгкой дуге и прибывает точно к сигналу; клик — короткий squash, затем цель
реагирует. Никогда не закрывает набираемые слова: кликай поле с дальней стороны.
**Логотипы партнёров:** инлайн, ~0,82 от кегля текста.
**Фирменная текстура:** только если она у продукта есть; спокойно за UI, разрежена за словами, никогда не плашкой.

## 5. Музыка: измерь песню, режь по тактам

- Сетка: темп автокорреляцией + гребёнка, фаза — лучший сдвиг гребёнки; даунбит — где стемы входят/выходят. Разброс сетки < 10 мс.
- **Карта песни** по громкости стемов на такт: интро, тихие такты, дропы, брейкдауны, большие удары. «Привет» — на редком такте, клик — в тихом, первые панчлайны — где входят барабаны, плотные фичи — на полном груве, главный момент — на дропе, финальный заголовок — где уходит бас, «домой» — на звенящем хвосте.
- **Монтаж трека по тактам** (`edit.json`: сегменты `fromBar..toBar`, 5 мс фейды на стыках); длина фильма = целое число тактов; медленное интро обычно режь.
- **SFX:** короткие, сухие, тихие (0,25–0,5); измерь время пика каждого файла и ставь его на `cue − peak`, чтобы транзиент лёг в кадр. Один звук на значимое событие.
- У нас: темп/доли — `librosa` (см. `sound.md` §6), монтаж — ffmpeg `atrim`+`concat` с `afade` 5 мс.

## 6. Ревью и ловушки

- Стоп-кадры на каждой передаче (handoff) + debug-оверлей с измерениями; контакт-лист черновика в половину разрешения; «handoff sheet» — 8 кадров через 0,1 с вокруг каждой передачи.
- Чек-лист: один цвет фона, никаких выдуманных оттенков и рамок; текст поверх всего, не закрыт курсором, не пересекает другой текст, не перецентровывается; кнопки в состоянии загрузки держат ширину; нет мёртвых тактов; передачи приземляются точно (измерено); цикл замкнут.
- **Цветовой диапазон:** мастер Remotion — limited range BT.601 без тегов; если блендить как full range, `#0a0a0a` становится `#171717` (серый прямоугольник на тёмной странице). Декодируй кадр 0 каждого файла и сверь числа. Наш рендерер тегирует bt709 — всё равно проверяй.
- Пунктирные CSS-рамки «ползут» при ресайзе — рисуй штрихи SVG с фиксированным шагом. WebGL-эффекты на своих часах рисуют каждый раз разное — текстуры рисуй покадрово.

## 7. html-demo: «записанное» окно приложения, которое на самом деле HTML

Для лендинга, где нужно живое окно продукта (не MP4): резкое на любом DPI, текст настоящий, можно перематывать,
замораживать, показывать reduced motion — всё из одного кода.

- **Всё — чистая функция одного числа.** `View({ t })` рисует содержимое окна на фиксированной сцене **1200×750** от `t`; одна CSS-масштабировка `--k = width / 1200` вписывает её. Никакой адаптивной вёрстки внутри окна.
- **Шаги:** 3–5 на окно по 4–8 с (18–30 с всего): увидеть старт (0,3–1 с) → действие → результат «как в приложении» (рабочее состояние → результат → осадка) → держать ≥ 1 с. Имена шагов 1–3 слова.
- **Времена — именованными константами** (`TYPE_FROM = 1.9, SEND_AT = 4.3, DONE_AT = 6.9`), состояние — сравнениями; движение — `ease(t,a,b)`, набор — `typed()`, списки изменений — `cue()`, клики — `held()`.
- **Курсор как человек:** прибывает за 0,3–0,6 с до клика, нажатие 0,15–0,2 с (стрелка 1.15 → 0.98), переезд 0,5–0,9 с `cubic-bezier(0.55,0,0.25,1)`; целится в 55 % ширины и 60 % высоты цели; цели измеряются из DOM (`data-aim`), не хардкодом. Следствие клика — через 0,05–0,15 с после него.
- **Набор текста** ~50 символов/с. **Проявление результата:** `clip-path: inset(0 0 100% 0) → inset(0)` под 2 px «сканирующей» линией поверх тусклой копии (`blur(10px) brightness(0.5) saturate(0.4)`, scale 1.08), затем осадка от `brightness(1.35)` за 0,9 с с бликом.
- **Честное сжатие времени:** минуты в секундах, но числа правдивые («Сделано 5 вещей за 2:14», 18 с приложения на секунду демо).
- **Только реальные слова и результаты:** каждую надпись — из исходников приложения (grep), ни одного выдуманного «Processing…».
- **Играть, только когда видно:** `IntersectionObserver` (0,3; 0,15 для героя), пауза при `document.hidden`, `dt ≤ 0.25 с`, тик 40–50 мс, перерисовка только при смене сигнатуры кадра.
- **Reduced motion = продуманные финальные кадры** (`t = dur` каждого шага), панель шагов продолжает работать.
- Один CSS-префикс на окно (классы и `@keyframes`); `role="img"` + `aria-label` со списком шагов; `<figure>` с `margin: 0`; переход между сценами — с лагом 300 мс, вход шага 0,45 с `cubic-bezier(0.2,0.7,0.1,1)`; камера до 1,2× на текущем шаге, глайд 1,3 с `cubic-bezier(0.45,0,0.2,1)`.
- **Hero-вариант (фильм):** весь ролик — `frameAt(t)` → описание кадра; потоки шагов вычисляются из графа зависимостей (шаг стартует, когда готовы входы, + 0,3 с), а не таймятся вручную.
- Проверка: замороженный кадр одинаков при каждом запуске; ширины 390 и 340 px без горизонтального скролла; консоль чистая.
